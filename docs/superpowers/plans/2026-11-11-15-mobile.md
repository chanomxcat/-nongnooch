# Mobile (Flutter) Tourist + Agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** แอป Flutter ชุดเดียว (`apps/mobile`) build ได้ 2 Flavor (Tourist / Agent) × 2 สโตร์ (GMS / HMS) นักท่องเที่ยวสมัคร / Login, ดูเนื้อหา (หน้าแรก, การแสดง + ตั้งเตือน, แผนที่, FAQ), ซื้อบัตร, เปิดบัตรได้แม้ออฟไลน์, ส่งบัตรให้เพื่อน, ดูพ้อย, รับ Push และจัดการโปรไฟล์ / ผู้ติดตาม / ลบบัญชีได้ ส่วนไกด์ใช้ Agent App ดู Invite QR และยอดผู้สมัคร พร้อม store listing 7 ภาษาและขั้นตอน build / ส่งตรวจ

**Architecture:** โค้ด Dart ชุดเดียว entrypoint 2 ไฟล์ (`main_tourist.dart`, `main_agent.dart`) เรียก backend ผ่าน gateway ด้วย client ที่ generate ไว้ใน `gen/dart` (dart-dio) ส่วนที่ต่างตามสโตร์ (Push, Google Sign-In) แยกเป็น package `store_impl` 2 ชุด (`store_gms`, `store_hms`) ที่มี API เดียวกัน และ `make mobile-build` เลือกชุดด้วย `pubspec_overrides.yaml` HMS build จึงไม่มี dependency ของ Google เลย ระบบภายนอกทุกตัวในโหมด demo ชี้ไป mockext ผ่าน `--dart-define`

**Tech Stack:** Flutter 3.24.0 / Dart 3.5, `go_router`, `flutter_riverpod`, `dio` (จาก `gen/dart`), `flutter_secure_storage`, `path_provider`, `qr_flutter`, `flutter_web_auth_2`, `flutter_local_notifications`, `share_plus`, `url_launcher`, `flutter_svg`, `flutter_localizations` + gen-l10n (ARB), `mocktail`, `integration_test` · เฉพาะ `store_gms`: `firebase_core`, `firebase_messaging`, `google_sign_in` · เฉพาะ `store_hms`: `huawei_push` · fastlane (metadata) สำหรับ store listing

**Spec:** [docs/system-design.md](../../system-design.md) F1, F2, F3, F11, S1, S2, S3, S7, หัวข้อ 2 (Mobile, Push, Social login) · [ROADMAP.md](../../../roadmap/ROADMAP.md) 4.2 E5, E9, E10 · [DESIGN.md](../../design/DESIGN.md) หัวข้อ 2, 3.3, 5, 7, 8 · [contracts](2026-11-11-contracts.md) (binding) · ขึ้นกับ [Plan 00 mockext](2026-11-11-00-mock-external.md), [Plan 01](2026-11-11-01-platform-chassis.md) Task 7 (`gen/dart`), [Plan 02](2026-11-11-02-identity-otp.md) และ Plan 03–13 ที่ยังไม่เขียน (endpoint ที่สมมติไว้อยู่ใน Interfaces ของแต่ละ task)

## Review Focus

1. **เปิดบัตรที่ประตูตอนไม่มีสัญญาณ:** เปิดแอปแบบ cold start ในโหมดเครื่องบินต้องเห็น QR จาก cache ทันทีพร้อมป้าย "อัปเดตล่าสุดเมื่อ …" และบัตรที่ cache รู้ว่า `transferred` / `void` ต้องไม่แสดง QR (Task 6)
2. **Deep link มาตอน cold start หรือก่อน Login:** invite code ต้องติดไปจนถึง `POST /members` แม้ผู้ใช้ผ่านหน้า OTP, social login และปิดแอประหว่างทาง (Task 2, Task 3)
3. **Access token หมดอายุพร้อมกันหลายคำขอ:** 401 หลายตัวพร้อมกันต้อง refresh แค่ครั้งเดียวแล้ว retry ทุกตัว และ `401 refresh_reused` ต้อง logout ทันที ไม่วน refresh (Task 2)
4. **ออกจากหน้าชำระเงินผิดทาง:** ผู้ใช้ปิด in-app browser เอง หรือแอปถูก kill ระหว่างจ่าย เมื่อกลับมาต้อง poll ออเดอร์ที่ค้างต่อ และถ้าเกิน 15 นาทีต้องแจ้งว่าการจองหมดเวลา ไม่ใช่ค้างหน้า loading (Task 5)
5. **ภาษา DE คำยาว และตัวอักษรขนาดใหญ่:** ปุ่มหลัก, Bottom Navigation และการ์ด MY TICKET ต้องไม่ overflow ที่ `de` + `textScaler 1.3` และภาษาเครื่องที่ไม่รองรับ (เช่น `ru`) ต้องได้ `en` (Task 1)
