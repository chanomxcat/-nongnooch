# Infra: Demo Host, CI/CD, Edge, Secrets, Observability, Backup, QA Harness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ให้ระบบ demo ทั้งชุด (8 service + gateway + mockext + web / admin / gate) รันบน **VM Linux 1 เครื่อง** ด้วย Docker Compose ชุดเดียวกับ local มี TLS + rate limit ที่ขอบ (Caddy), secret เข้ารหัสด้วย sops, CI/CD ผ่าน GitHub Actions + GHCR พร้อมผู้อนุมัติก่อน deploy, observability (OTel → Grafana LGTM) + alert, backup อัตโนมัติ + ทดสอบกู้คืน, `make seed` / `make demo-reset` และชุดทดสอบ load (k6) / security (ZAP) / ซ้อม deploy + rollback

**Architecture:** ใช้ `deploy/compose.yaml` ของ Plan 01 เป็นฐาน แล้วซ้อนด้วย `deploy/compose.demo.yaml` (image จาก GHCR, secret จาก env_file, ไม่เปิดพอร์ตอื่นนอกจาก Caddy 80/443, volume ถาวร, resource limit) งาน ops ทุกอย่าง (sops, mariadb-dump, mc, nats CLI) รันใน container `ops` ตัวเดียว ส่วนสคริปต์ shell บน host เรียกแค่ `docker` / `make` / `git` / `ssh` CI สร้าง image ทุกตัวด้วย tag = git sha แล้ว deploy ด้วยการส่งโฟลเดอร์ `deploy/` + `scripts/` ของ sha นั้นไปที่ VM (`git archive` ผ่าน ssh) ไม่ต้องให้ VM เข้าถึง repo

**Tech Stack:** Docker Engine 27 + Compose ≥ 2.24 (`!reset`, `!override`), Ubuntu 24.04 LTS + cloud-init, Caddy 2.8 + `github.com/mholt/caddy-ratelimit` (xcaddy), sops 3.9 + age 1.2, GitHub Actions + GHCR, `otel/opentelemetry-collector-contrib` 0.110, `grafana/otel-lgtm` 0.8, `grafana/k6` 0.54, `ghcr.io/zaproxy/zaproxy` 2.15, `drwetter/testssl.sh` 3.2, `bats/bats` 1.11, `rhysd/actionlint` 1.7, `zricethezav/gitleaks` v8.21

## Review Focus

1. **Rollback หลัง migration ใหม่รันไปแล้ว:** image เวอร์ชันก่อนต้อง start ได้บน schema ที่ใหม่กว่า (goose เห็น version ใน DB สูงกว่าไฟล์ที่ตัวเองมี) และ migration ต้องเป็นแบบ expand-only (Task 6 rehearse, Task 7 `check-migrations`)
2. **Volume ต้องเป็นตัวเดิมข้าม release:** deploy จากโฟลเดอร์ release ใหม่ต้องไม่สร้าง volume ว่างใหม่ (project name ตายตัว `-p nongnooch-demo`) ไม่อย่างนั้นข้อมูล demo หายทั้งก้อน (Task 2, Task 6)
3. **ปลอม `X-Forwarded-For` / `LOADTEST_KEY` ว่างหรือผิด:** ต้องไม่หลบ rate limit ได้ และ identity ต้องเห็น IP จริงของ client (Task 3)
4. **Secret หลายบรรทัด (PEM Ed25519) ผ่าน sops dotenv → `env_file`:** ต้องถึง container เป็น PEM ที่ parse ได้ ไม่ใช่ `\n` ตัวอักษร (Task 1, Task 2)
5. **Basic auth หน้า mock ขวางนักท่องเที่ยว:** `mock.<domain>` ต้องยกเว้น `/oauth/*` และ `/pg/checkout/*` ไม่อย่างนั้น Social login และหน้าจ่ายเงินจำลองใช้ไม่ได้ระหว่าง demo (Task 3)
