# Admin / CMS / Dashboard + Gate Scanner Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** เจ้าหน้าที่นงนุชล็อกอินด้วยบัญชี staff แล้วเห็นเมนูตามบทบาท แก้เนื้อหา 7 ภาษา ราคา โปรโมชัน Agent ออเดอร์ สมาชิก ดู Dashboard และคุมระบบได้เองใน `apps/admin` โดยทุกการเปลี่ยนเนื้อหาและราคาผ่าน Workflow อนุมัติ (four-eyes) ส่วนเจ้าหน้าที่ประตูใช้ `apps/gate` (PWA) สแกน QR ตรวจลายเซ็น Ed25519 ในเครื่องได้ผลภายใน 1 วินาทีทั้งตอนออนไลน์และออฟไลน์ แล้ว sync เมื่อเน็ตกลับมา

**Architecture:** Next.js 2 แอปใน monorepo ใช้แพ็กเกจร่วม `packages/staff-kit` (session ของ staff, API client จาก `gen/ts`, บทบาท, format เงิน / เวลา) ทุกคำขอไป gateway `http://localhost:8000/api/<svc>/...` เท่านั้น staff token (8 ชม. ไม่มี refresh) เก็บใน cookie httpOnly ผ่าน route handler ของแต่ละแอป และคัดลอกไว้ในหน่วยความจำตอนใช้งาน ฝั่ง Gate แยก logic ตรวจบัตรเป็นฟังก์ชันบริสุทธิ์ (`verifyQr`, `decide`) ที่ไม่แตะ network และใช้ IndexedDB เก็บ snapshot + คิว scan โดย sync เป็น batch แบบ idempotent ด้วย `scanId`

**Tech Stack:** Next.js 14 (App Router, TypeScript strict), React 18, `openapi-fetch` + type จาก `gen/ts` (openapi-typescript), `tweetnacl` (Ed25519), `idb` (IndexedDB), `@zxing/browser` (กล้อง), `@serwist/next` (service worker), `recharts`, `react-markdown`, Vitest + Testing Library + `msw` v2 + `fake-indexeddb`, Playwright (`mcr.microsoft.com/playwright:v1.48.2-jammy`)

**Spec:** [docs/system-design.md](../../system-design.md) F2, F4, F5, S4, S5, S6, S7, หัวข้อ 2 (แถว Gate Scanner, CMS), Q2, Q3, Q5 · [ROADMAP.md](../../../roadmap/ROADMAP.md) 4.2 E4, E6, E7, E10 · [DESIGN.md](../../design/DESIGN.md) · [contracts](2026-11-11-contracts.md) (ผูกมัด) · ขึ้นกับ [Plan 01](2026-11-11-01-platform-chassis.md) Task 7 (`make gen`), [Plan 02](2026-11-11-02-identity-otp.md) (JWKS), Plan 04 (staff login, content, approval), Plan 13 Task 1 (`packages/tokens`)

## Review Focus

1. **นาฬิกาเครื่องประตูกับวันเข้าชม:** สแกนเวลา 06:30 น. ไทย (= 23:30 UTC ของเมื่อวาน) ต้องถือว่าเป็น "วันนี้" ตาม Asia/Bangkok บัตรของวันนี้ต้องได้ `ok` ไม่ใช่ `wrong_date` และ snapshot ที่โหลดต้องเป็นของวันไทย (Task 7, Task 8)
2. **กล้องอ่าน QR เดิมหลายครั้งต่อวินาที:** ผลแรกต้องค้างบนจอ และการอ่านซ้ำภายใน 3 วินาทีต้องไม่ทำให้ลูกค้าคนเดิมเห็น "ใช้แล้ว" หรือเกิดแถวในคิวเพิ่ม (Task 8)
3. **sync ขาดกลางทาง:** server ได้ batch แล้วแต่คำตอบหาย เครื่องส่งซ้ำด้วย `scanId` เดิม ต้องไม่ถูกนับเป็นการสแกนซ้ำข้ามประตู และคิวต้องว่างหลังได้คำตอบ (Task 8)
4. **ตัวเลขเงินที่พิมพ์หลายรูปแบบ:** `"1,250.50"`, `"550"`, `"0.1"` แปลงเป็นสตางค์ได้ตรง ส่วน `"12.345"`, `"-5"`, `""`, `"1e3"` ต้องเป็น error ในฟอร์ม ไม่ส่งค่าที่ปัดเศษผิดไปขออนุมัติ (Task 1, Task 4)
5. **แก้พร้อมกัน / token หมดอายุระหว่างแก้:** สองคนแก้ร่างเดียวกัน คนที่บันทึกทีหลังต้องได้ข้อความ `version_conflict` และข้อความที่พิมพ์ยังอยู่ ส่วน staff token 8 ชั่วโมง (ไม่มี refresh ตาม contracts หัวข้อ 3) หมดระหว่างกรอกเนื้อหายาว ต้องเปิด dialog ล็อกอินซ้ำในหน้าเดิมแล้วบันทึกต่อได้โดยข้อความที่พิมพ์ไม่หาย (Task 1, Task 2)
