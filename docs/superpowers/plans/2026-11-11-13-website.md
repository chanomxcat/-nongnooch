# Website (Next.js) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** เว็บนักท่องเที่ยว 7 ภาษา (`apps/web`) ตาม Concept A ที่สมัครสมาชิกด้วย OTP / Social login + Invite code ได้ ซื้อบัตร 4 ขั้นพร้อมระบุผู้ใช้บัตรรายใบ + Upsell + จ่ายผ่าน mockext แล้วเห็น QR ในหน้าบัตรของฉัน มีหน้าข้อมูลสวนจาก CMS หน้า Agent, Web Push / PWA และผ่าน SEO / LCP / WCAG ตาม E1 พร้อม design tokens + ชุดไอคอนที่ใช้ร่วมกับ Flutter (`packages/tokens`)

**Architecture:** Next.js App Router ใต้ `app/[locale]/` (next-intl) หน้า public ดึง CMS แบบ SSR + ISR 60 วิ ผ่าน gateway โดยตรงจาก server ส่วนหน้าที่ต้อง login (สมัคร, checkout, บัตร, Agent) เป็น client component ที่เรียก **BFF** ใน Next เอง (`/bff/*` route handler) ซึ่งเก็บ access / refresh token ใน cookie แบบ httpOnly แล้วส่งต่อไป gateway `/api/<svc>` พร้อม Bearer ทำให้ token ไม่อยู่ใน JavaScript ของหน้า client ทุกตัวใช้ type จาก `gen/ts/<svc>.ts` (openapi-typescript, Plan 01 Task 7) ผ่าน `openapi-fetch` ส่วน token สี / ระยะ / ไอคอนมาจาก `packages/tokens` ไฟล์เดียวที่ build เป็น CSS variables + Dart

**Tech Stack:** Node 20, Next.js 15 (App Router, React 19, `output: "standalone"`), TypeScript 5, `next-intl` 4, CSS Modules + CSS custom properties (ไม่ใช้ Tailwind), `openapi-fetch`, `swr`, `qrcode`, `libphonenumber-js` (min metadata), `@fontsource/*` (โฮสต์เอง), `svgo`, `esbuild` (service worker), Vitest 2 + `@testing-library/react` + jsdom, Playwright 1.48 + `@axe-core/playwright`, `@lhci/cli`

## Review Focus

1. **access token หมดอายุระหว่างที่หน้าเว็บยิงหลายคำขอพร้อมกัน:** ทุกคำขอได้ 401 แล้วต่างคน refresh ด้วย refresh token เดิม identity จะตอบ `refresh_reused` และ revoke ทุก token (Plan 02 Task 4) ผู้ใช้ถูก logout กลาง checkout · BFF ต้อง refresh แบบ single-flight ต่อ refresh token (Task 2)
2. **IP จริงของผู้ใช้หายเมื่อผ่าน BFF:** ทุกคำขอจะมาจาก IP ของ container web ทำให้ rate limit 20 ครั้ง / IP / ชั่วโมงของ OTP ใช้ร่วมกันทั้งเว็บ และธง `same_ip` ของ referral ผิดทุกคน · BFF ต้องส่ง `X-Forwarded-For` และ gateway ต้องเชื่อจาก proxy ที่ไว้ใจ (Task 2 + contracts หัวข้อ 2 `TRUSTED_PROXIES`)
3. **กดย้อนกลับ / reload / กดซ้ำรอบการจองและชำระเงิน:** ต้องไม่สร้าง hold ซ้ำ และกลับจาก mockext แล้ว reload หน้าผลต้องยังเห็นสถานะของออเดอร์เดิม (Task 5 `Idempotency-Key` + resume, Task 6 path `/checkout/result/[orderId]`)
4. **นาฬิกาเครื่องผู้ใช้ผิด:** ตัวจับเวลา 15 นาทีต้องนับจาก `holdExpiresAt` เทียบเวลา server (header `Date`) ไม่ใช่ `Date.now()` ของเครื่อง (Task 6)
5. **Invite code หายระหว่างทาง:** ผู้ใช้เปิด `/<l>/r/{inviteCode}` (หรือ `?invite=`) แล้วออกไป login ที่ IdP, สลับภาษา หรือไปเช็ก OTP ในอีเมลแท็บอื่น ต้องยังส่ง `inviteCode` ตอน `POST /members` (Task 2 middleware cookie, Task 4 social callback)
