# Report: Read model, Dashboard API, Export + Funnel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** service `report` สร้าง read model จาก event (ยอดขาย, คืนเงิน, สมาชิก, referral ของ Agent, พ้อย, สแกนประตู, ส่งบัตร) แบบ idempotent แล้วเปิด Dashboard API ให้ผู้บริหารเห็นยอดขาย / สมาชิก / Agent / คนเข้าประตูรายชั่วโมง หน่วงไม่เกิน 1 นาที พร้อม Export CSV / Excel รายวันสำหรับกระทบยอด และเก็บ funnel event แบบ GA4 ฝั่ง server

**Architecture:** consumer ตัวเดียว (`report`) รับ 9 event (`order.paid`, `order.refunded`, `member.registered`, `member.consent_changed`, `account.deleted`, `referral.created`, `points.changed`, `ticket.scanned`, `ticket.transferred`) แล้วเขียนลง **fact table ที่ใช้ ID ธรรมชาติของ event เป็น primary key** (`order_item_id`, `refund_id`, `member_id`, `referral_id`, `entry_id`, event id) ด้วย `INSERT IGNORE` จึง idempotent สองชั้น (ชั้นแรกคือ `processed_events` ของ chassis) Dashboard คำนวณ aggregate ตอน query จาก fact table ที่มี index ตามวัน (เวลา Asia/Bangkok เก็บเป็นคอลัมน์ `bkk_date` / `bkk_hour` ตอน insert) ไม่มี cache จึงหน่วงเท่ากับเวลาที่ event มาถึง consumer funnel event จากเว็บ / แอปรับผ่าน `POST /analytics/collect` รูปแบบเดียวกับ GA4 Measurement Protocol และเก็บใน schema `report` ส่วนการส่งต่อไป GA4 จริงอยู่หลัง interface `Forwarder` ที่ demo ใช้ตัวที่ log อย่างเดียว

**Tech Stack:** Go 1.23 + chassis (Plan 01), `pkg/chassis/authn` (Plan 12 Task 1), `encoding/csv`, `github.com/xuri/excelize/v2` (ไม่ต้องเรียก gRPC ของ member เพราะ `member.registered` มี `marketingConsent` แล้ว)

**Spec:** [docs/system-design.md](../../system-design.md) 1.2 (แถว Report), 1.3 Event Map (O3) · [ROADMAP.md](../../../roadmap/ROADMAP.md) 4.2 E7 (Dashboard และรายงาน), E8 (Analytics), E9 (PDPA) · [contracts](2026-11-11-contracts.md) §1, §3, §4, §5, §7 · ขึ้นกับ [Plan 01](2026-11-11-01-platform-chassis.md) · หน้า Dashboard อยู่ใน Plan 14

## Review Focus

1. **event เดียวกันมาซ้ำ หรือคนละ envelope แต่ ID ธรรมชาติเดียวกัน** (เช่น publish `order.paid` ซ้ำหลัง relay crash): ตัวเลข dashboard ต้องไม่เพิ่ม (Task 1: `TestOrderPaidTwiceCountsOnce`, Task 2: `TestReferralTwiceCountsOnce`)
2. **เวลาข้ามเที่ยงคืน UTC / Bangkok:** ออเดอร์ 23:30 UTC = 06:30 วันถัดไปที่ Bangkok ต้องไปอยู่ "วันนี้" ของ Bangkok ไม่ใช่เมื่อวาน (Task 1: `TestBangkokDateBucket`, Task 3: `TestTodayUsesBangkokMidnight`)
3. **สแกน offline ที่ sync มาช้า:** ต้องนับในชั่วโมงของ `scannedAt` ไม่ใช่เวลาที่ event มาถึง และสแกนซ้ำ (`duplicate=true`) ไม่นับเป็นคนเข้า (Task 2: `TestLateOfflineScanBucketsByScannedAt`, Task 4: `TestDuplicateScanNotCounted`)
4. **ภาษาไทยใน Excel และ CSV:** เปิดด้วย Excel แล้วไม่เป็นตัวอักษรเพี้ยน (CSV ต้องมี UTF-8 BOM) และยอดเงินเป็นบาททศนิยม 2 ตำแหน่งตรงกับสตางค์ (Task 5: `TestCSVHasBOMAndThai`, `TestAmountFormatting`)
5. **`/analytics/collect` เปิดสาธารณะ:** body ใหญ่, ชื่อ event มั่ว, หรือแนบอีเมล / เบอร์มาใน params ต้องถูกปฏิเสธหรือตัดทิ้ง ไม่เก็บ PII (Task 6: `TestCollectRejectsOversize`, `TestCollectDropsPIIParams`)

  - params ที่เก็บ: string / number ≤ 100 ตัวอักษร ไม่เกิน 25 key, ตัด key ที่ชื่อมี `email|phone|name|id_card|passport` และค่าที่ดูเป็นอีเมล (`@`) หรือเบอร์ (`^\+?\d{9,15}$`) ทิ้ง · เก็บ `utm_source`, `utm_medium`, `utm_campaign`, `lang`, `item_kind`, `value`
  - server-side: `member.registered` → `sign_up {method: channel, source}` (`client_id` = `deviceId`, `user_id` = memberId) · `order.paid` → `purchase {transaction_id: orderNo, value: paidAmountSatang/100, currency: "THB", items: kind[]}` (`client_id` = `"server"`, `user_id` = memberId)
  - `type Forwarder interface { Forward(ctx context.Context, ev AnalyticsEvent) error }` + `LogForwarder` (slog INFO ไม่มี params ที่ถูกตัด) · ตัวส่ง GA4 จริง (`GA4Forwarder` ใช้ env `GA4_MEASUREMENT_ID`, `GA4_API_SECRET`) **ไม่ทำใน demo** ให้ `main.go` เลือก `LogForwarder` เสมอเมื่อ env ว่าง · forward ทำหลัง commit ถ้า error แค่ log
  - `GET /dashboard/funnel?kind=purchase|signup&from=&to=` (role `admin`, `viewer`) → `{kind, steps: [{name, count}], asOf}` · purchase = `view_item → add_to_cart → begin_checkout → purchase` · signup = `sign_up_start → otp_verified → sign_up` · step ของ client นับ distinct `client_id`, `purchase` นับ distinct `transaction_id`, `sign_up` นับ distinct `user_id`

```sql
CREATE TABLE analytics_events (id CHAR(36) PRIMARY KEY, source ENUM('client','server') NOT NULL,

  params JSON NOT NULL, occurred_at DATETIME(6) NOT NULL, bkk_date DATE NOT NULL,
  INDEX idx_name_date (name, bkk_date)) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```
