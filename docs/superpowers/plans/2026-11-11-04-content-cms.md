# Content (CMS) + Approval + RBAC Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ทีมนงนุชแก้เนื้อหา 7 ภาษา (หน้าเว็บ, ตารางการแสดง, FAQ, เบอร์ฉุกเฉิน, โซน / หมุดแผนที่) และรูปภาพได้เอง มี Preview ทุกการเปลี่ยนผ่าน Workflow อนุมัติแบบ four-eyes พร้อม AuditLog และเมื่ออนุมัติแล้วระบบส่ง event `content.published` / `price.approved` และล้าง cache เจ้าหน้าที่ล็อกอินด้วยอีเมล + รหัสผ่านและได้สิทธิ์ตาม 7 บทบาท

**Architecture:** service `content` (schema `content`) สร้างบน chassis (Plan 01) เนื้อหาทุกชนิดเก็บแบบ generic: `content_items` + `content_revisions` (attrs ที่ไม่แปล + texts แยกภาษา เป็น JSON) โดยมี type registry ในโค้ดกำหนดฟิลด์และกติกาตรวจของแต่ละชนิด ทุกการแก้เป็น `ApprovalRequest` (draft → pending → approved / rejected) ซึ่งตอนอนุมัติจะเขียน `published_rev_id`, AuditLog และ outbox ใน transaction เดียว การล้าง cache ทำใน consumer ของ event ตัวเอง (ได้ retry + DLQ จาก chassis) ส่วน staff login อยู่ใน service `identity` ตาม contracts หัวข้อ 3 รูปแปลงเป็น WebP / AVIF ตอนอัปโหลดด้วยไลบรารี Go ล้วน แล้วเก็บใน MinIO

**Tech Stack:** Go 1.23 + chassis (Plan 01), `pkg/chassis/authn` (Plan 12 Task 1), `golang.org/x/crypto/bcrypt`, `github.com/minio/minio-go/v7`, `github.com/disintegration/imaging` (decode + EXIF auto-orient + resize), `github.com/gen2brain/webp` และ `github.com/gen2brain/avif` (encoder แบบ WASM ผ่าน wazero ไม่ใช้ CGO)

**Spec:** [docs/system-design.md](../../system-design.md) F5, หัวข้อ 1.2 (แถว Content), หัวข้อ 2 (CMS, ไฟล์), Q5, Q22, Q28 · [roadmap/ROADMAP.md](../../../roadmap/ROADMAP.md) หัวข้อ 4.2 E6 · [contracts](2026-11-11-contracts.md) หัวข้อ 3, 5, 7 · ขึ้นกับ [Plan 01](2026-11-11-01-platform-chassis.md), [Plan 02](2026-11-11-02-identity-otp.md) (TokenIssuer, JWKS) และ [Plan 12](2026-11-11-12-api-gateway.md) Task 1 (`authn`)

## Review Focus

1. **อนุมัติงานตัวเอง:** ผู้ที่เคยแก้ draft นั้น (ไม่ใช่แค่คนสร้าง) แม้มีบทบาท `admin` + `approver` ต้องอนุมัติไม่ได้ ได้ `403 four_eyes_violation` (Task 5)
2. **อนุมัติซ้อน / แก้ระหว่างรออนุมัติ:** approver 2 คนกดอนุมัติพร้อมกันต้องสำเร็จครั้งเดียวและมี outbox 1 แถว ส่วนการแก้ draft ที่ `pending` แล้วต้องได้ `409 not_editable` เพื่อให้สิ่งที่อนุมัติตรงกับสิ่งที่ approver เห็น (Task 5)
3. **หมุดอ้างโซนที่ไม่มีจริง:** POI ที่ zoneId ชี้ไปโซนที่ยังไม่เผยแพร่ หรือโซนถูกถอนระหว่างรออนุมัติ ต้องอนุมัติไม่ได้ (`409 zone_not_found`) และถอนโซนที่ยังมีหมุดเผยแพร่อยู่ไม่ได้ (`409 zone_in_use`) (Task 6)
4. **คำแปลที่เป็นช่องว่าง / ภาษาที่ไม่รองรับ:** ค่า `"  "` ต้องนับว่ายังไม่แปลและใช้ EN แทน, `lang=ru` หรือ `zh-TW` ต้องได้ EN ไม่ใช่ 400 หรือข้อความว่าง (Task 1, Task 7)
5. **รูปจากมือถือ:** JPEG ที่มี EXIF orientation ต้องหมุนถูก, ไฟล์ต้นฉบับที่มี GPS ห้ามเปิดสาธารณะ, ไฟล์ปลอมนามสกุล `.jpg` และรูปขนาด 30000×30000 ต้องได้ 4xx ไม่ใช่ OOM (Task 4)

  - `func Resolve(t Texts, fields []Field, lang string) (out map[string]string, fallback []string)` ค่าที่ `strings.TrimSpace` แล้วว่างนับว่าไม่มี ใช้ `en` แทนและใส่ชื่อฟิลด์ใน `fallback`
  - `type Field struct { Name string; Required bool; MaxLen int }`
  - `type TypeSpec struct { Name string; Fields []Field; ValidateAttrs func(ctx context.Context, attrs json.RawMessage, l Lookup) error; SitePath string }` และ `func Spec(name string) (TypeSpec, bool)` · Task นี้ลงทะเบียน `page` (fields `title` บังคับ 120, `summary` 300, `body` บังคับ 20000 เป็น Markdown; attrs `{heroMediaId?}`; SitePath `/{lang}/{slug}`) ชนิดอื่นเพิ่มใน Task 6
  - `type Lookup interface { PublishedType(ctx, id string) (string, bool, error); MediaExists(ctx, id string) (bool, error) }` (Task 4, 6 ใช้)
  - `func ValidateForSubmit(spec TypeSpec, t Texts) error` คืน `*FieldError{Field, Lang, Code}` เมื่อฟิลด์บังคับขาด `th` หรือ `en` (code `required`) หรือยาวเกิน (code `too_long`, นับ rune)
  - HTTP สาธารณะ: `GET /public/contents?type=&lang=&zoneId=&cursor=&limit=` และ `GET /public/contents/{id}?lang=` คืน `{id, type, slug, sortOrder, attrs, texts: {field: value}, lang, fallback: [...], media: {id: Media}, updatedAt}` เฉพาะที่เผยแพร่แล้ว เรียงตาม `sortOrder` แล้ว `id` · lang มาจาก query ก่อน แล้ว `authn.From(ctx).Lang` แล้ว `en` · header `Cache-Control: public, max-age=60, s-maxage=600` · `type` ไม่รู้จักได้ `400 unknown_type`, ไม่พบ `404 not_found`

ตาราง:

```sql
CREATE TABLE content_items (
  id CHAR(36) PRIMARY KEY, type VARCHAR(32) NOT NULL, slug VARCHAR(128) NOT NULL,
  published_rev_id CHAR(36) NULL, sort_order INT NOT NULL DEFAULT 0,
  created_at DATETIME(6) NOT NULL, updated_at DATETIME(6) NOT NULL,
  UNIQUE KEY uq_type_slug (type, slug), INDEX idx_type_pub (type, published_rev_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
CREATE TABLE content_revisions (
  id CHAR(36) PRIMARY KEY, item_id CHAR(36) NOT NULL,
  attrs LONGTEXT NOT NULL, texts LONGTEXT NOT NULL,   -- JSON
  created_by CHAR(36) NOT NULL, created_at DATETIME(6) NOT NULL, INDEX idx_item (item_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
CREATE TABLE approval_requests (
  id CHAR(36) PRIMARY KEY, kind VARCHAR(8) NOT NULL,          -- content | price
  action VARCHAR(16) NOT NULL,                               -- publish | unpublish | price
  item_id CHAR(36) NULL, revision_id CHAR(36) NULL, payload LONGTEXT NULL,  -- price: {"changes":[...]}
  status VARCHAR(16) NOT NULL, title VARCHAR(200) NOT NULL,
  editor_id CHAR(36) NOT NULL, contributors LONGTEXT NOT NULL,   -- JSON array staffId ที่เคยแก้
  version INT NOT NULL DEFAULT 1, submitted_at DATETIME(6) NULL,
  decided_by CHAR(36) NULL, decided_at DATETIME(6) NULL, reason VARCHAR(1000) NULL,
  created_at DATETIME(6) NOT NULL, updated_at DATETIME(6) NOT NULL,
  INDEX idx_status (status, kind, created_at), INDEX idx_item_status (item_id, status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
CREATE TABLE audit_logs (
  id CHAR(36) PRIMARY KEY, at DATETIME(6) NOT NULL, actor_id CHAR(36) NOT NULL, actor_roles VARCHAR(255) NOT NULL,
  action VARCHAR(48) NOT NULL, entity VARCHAR(32) NOT NULL, entity_id CHAR(36) NOT NULL,
  before_json LONGTEXT NULL, after_json LONGTEXT NULL, reason VARCHAR(1000) NULL, request_id VARCHAR(64) NULL,
  INDEX idx_entity (entity, entity_id, at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
CREATE TABLE media (
  id CHAR(36) PRIMARY KEY, filename VARCHAR(255) NOT NULL, mime VARCHAR(32) NOT NULL,
  width INT NOT NULL, height INT NOT NULL, bytes BIGINT NOT NULL, variants LONGTEXT NOT NULL,
  created_by CHAR(36) NOT NULL, created_at DATETIME(6) NOT NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```
